# Life Sorted: design record

## Purpose

Provide a visual bullet journal for tasks, schedules, reminders and progress.

## Elements

| Element | Documentation boundary |
| :-- | :-- |
| Journal entries | Included in the stated project scope. Implementation details need the corresponding source or design file. |
| Tasks | Included in the stated project scope. Implementation details need the corresponding source or design file. |
| Schedule | Included in the stated project scope. Implementation details need the corresponding source or design file. |
| Progress views | Included in the stated project scope. Implementation details need the corresponding source or design file. |

## Technical stack

- Web app
- Tasks
- Schedules
- Reminders

## Boundaries

Part numbers, interfaces, versions and measured outcomes must come from the original artifacts. They are not inferred from the project title.

## Decisions to recover

Record each design decision with its problem, selected option, rejected options and supporting artifact. Keep the original model or source revision with the record.
